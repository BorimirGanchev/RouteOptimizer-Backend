GitHub Actions
Workflow-ът е настроен във файла .github/workflows/main.yml и се стартира при push към branch feature (включително feature/*) и при pull_request към branch dev (редове 3-7). Създадена е една job секция lint-build-test, която се изпълнява на ubuntu-latest и работи в директория Backend (редове 9-14). След checkout на кода (редове 17-18) се настройва Node.js 20 с cache за npm и зависимост от Backend/package-lock.json (редове 20-25). После се инсталират зависимостите с npm install (редове 27-28). При успешен pipeline всички стъпки се маркират в зелено и PR може да бъде прегледан/сливан. При проблем (грешка в синтаксис, тест или linter) изпълнението спира на съответната стъпка и pull request-ът се маркира като failed check.

Pipeline Tests
Unit тестовете се стартират в стъпката "Run unit tests" чрез npm run test:ci (редове 36-37 във .github/workflows/main.yml). Командата test:ci е дефинирана в Backend/package.json в секцията scripts (ред 11) и изпълнява Jest с coverage в CI режим. Конфигурацията за Jest е в Backend/jest.config.cjs (редове 1-9), където е зададено събиране на покритие за модулите dataProcessing/dataExtraction.js и dataProcessing/dataProcessing.js (редове 4-7). Самите unit тестове са реализирани във файловете Backend/__tests__/dataExtraction.test.js и Backend/__tests__/dataProcessing.test.js.

Pipeline Linter
Linter-ът се стартира в стъпката "Run linter" чрез npm run lint (редове 30-31 във .github/workflows/main.yml). Командата lint е дефинирана в Backend/package.json в секцията scripts (ред 8) и използва ESLint. Конфигурацията е в Backend/eslint.config.cjs (редове 1-16), където е указано lint-ване на всички .js файлове (ред 6) и са игнорирани папките node_modules и coverage (ред 3). Допълнително са изключени правилата no-unused-vars и no-console (редове 12-13), за да е съвместимо с текущия код на проекта.
